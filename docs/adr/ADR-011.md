

### ADR-011: Implementazione REST API Server, Web App Pubblica e Area Socio Demo (Fase 2.2)
* **Data:** 2026-09-08
* **Contesto:** Con il completamento della Fase 2.1 (Hardening di Dominio e Scaffolding), si rende necessario attivare il primo stack web funzionante end-to-end (Browser → React → REST API → Application Services → Domain Policy → Repository). Il database relazionale definitivo (PostgreSQL) e l'infrastruttura completa di autenticazione/sessioni non sono ancora richiesti in questa fase.
* **Decisione:**
  1. **Server REST API Leggero e Tipizzato:** Implementato server HTTP basato su Express con parsing JSON, validatore input severo (`ActivityValidator`) e gestione esplicita dei codici HTTP (200, 400, 403, 404, 500) senza esporre stack trace.
  2. **Contratto REST Vetrina e Dettaglio (Nessun Bypass):** 
     - `GET /api/showcase`: restituisce solo attività con `PublicationStatus == PUBBLICATA` e `MembershipStatus == ATTIVO`.
     - `GET /api/activities/:id`: se l'attività non soddisfa i requisiti di visibilità pubblica restituisce 404, impedendo a chiunque di aggirare la vetrina tramite accesso diretto all'endpoint.
  3. **Ownership e Protezione Ruoli su `PUT /api/activities/:id`:** 
     - Modifica consentita solo ed esclusivamente se `actorRole == SOCIO` e `activity.memberId == actorMemberId`.
     - Riceve 403 Forbidden sia il Socio che tenti di modificare schede di altri soci, sia l'Amministratore Tecnico (che non ha alcun titolo sulle schede commerciali).
     - La modifica reimposta automaticamente lo stato su `IN_ATTESA_APPROVAZIONE` senza auto-approvazione.
  4. **Autenticazione DEMO Esplicita:** L'endpoint `GET /api/members/me` e le chiamate di mutazione utilizzano l'header di contesto demo `X-Demo-Member-Id` e `X-Demo-Role`, esplicitamente etichettati come non idonei alla produzione in attesa delle sessioni sicure della Fase successiva.
  5. **Astrazione Repository Preservata:** L'astrazione `IMemberRepository` e `IBusinessActivityRepository` continua a operare su implementazioni in-memory; nessun database relazionale operativo è stato introdotto prematuramente.
  6. **Interfaccia Web React Accessibile e Neutrale:** Create le viste web `/`, `/attivita/:id`, `/socio`, `/socio/attivita` con banner permanente `LegalNotice` e divieto categorico di badge o attestati commerciali.
* **Conseguenze:** Primo stack Web completo, testabile e verificato sia lato server (25 test unitari e REST superati) che lato client (test SSR dei componenti superati), con totale preservazione del prototipo Android.
